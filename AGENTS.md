# Contributor instructions

Keep this reusable package independent of employer/customer identifiers, contracts, private trackers and personal planning paths. Use neutral descriptive commit subjects.

Use ordinary Markdown and native tooling. Keep the library API reusable and the CLI thin. Use real production tests and actual native tools; do not rely on mocks, fake CLIs/services or alternate implementations of external behavior.

Use the repository Make checks. Preserve unrelated work and unknown artifacts; stage only explicitly owned paths. Never change Git identity. Stay on the locally authorized non-default branch; repository edits do not authorize remotes, pushes or publication.
